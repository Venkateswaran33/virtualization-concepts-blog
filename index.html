THE BIG IDEA

What is virtualization?

Virtualization uses software to create virtual versions of computing resources—such as computers, operating systems, storage, or networks. Instead of dedicating one physical machine to one workload, resources can be shared among multiple isolated environments.

01

Abstract

Separate the service or operating system from the underlying hardware.

02

Share

Use CPU, memory, storage, and network capacity more efficiently.

03

Isolate

Keep workloads separated so they can be managed independently.

01 / FOUNDATIONS

Hardware vs. software virtualization

These ideas are related, but they describe different layers of the system.

▦

Hardware virtualization

A hypervisor presents virtual hardware to guest operating systems. Each virtual machine can run its own OS and applications.

  • Commonly used for server consolidation
  • Supports different guest operating systems
  • Usually provides a strong VM boundary

Example: Three virtual servers running on one physical host.

</>

Software virtualization

Software creates an isolated or emulated environment for an application or system component, without always virtualizing an entire machine.

  • Can provide application compatibility
  • May virtualize runtime or application layers
  • Scope depends on the technology

Example: An application running in a managed runtime or compatibility layer.

Remember: “Software virtualization” is a broad term. Virtual machines are also created and managed by software, while containers and application virtualization work at different layers.

03 / THE VM LAYER

Meet the hypervisor

A hypervisor creates and runs virtual machines, allocating physical resources to each guest environment.

TYPE 1

Bare-metal

Runs directly on physical hardware

ApplicationsGuest operating systemsType-1 hypervisorPhysical hardware

Strengths

Common in data centers; generally offers efficient resource control and centralized management.

Considerations

May require dedicated infrastructure, compatible hardware, and specialist administration.

Examples: VMware ESXi, Microsoft Hyper-V, Xen.

TYPE 2

Hosted

Runs as an application on a host OS

ApplicationsGuest operating systemsType-2 hypervisorHost operating systemPhysical hardware

Strengths

Convenient for learning, desktop testing, demonstrations, and running another OS locally.

Considerations

Shares the host OS and its resource overhead; less typical for large production server estates.

Examples: Oracle VirtualBox, VMware Workstation.

Quick rule: Type 1 sits on the hardware; Type 2 sits on a host operating system.

04 / LIGHTWEIGHT ISOLATION

Containers: a different approach

Containers package an application with its libraries and configuration. They typically share the host operating-system kernel instead of running a separate guest OS for every container.

FeatureVirtual machineContainer
Operating systemEach VM includes a guest OSShares the host kernel
Typical footprintUsually largerUsually smaller
StartupOften slowerOften faster
Isolation boundaryVirtual hardware + guest OSOS-level isolation mechanisms
Common useDifferent OS environments, legacy systemsPortable application deployment, microservices

Important: Containers are not automatically a replacement for VMs. Many systems run containers inside virtual machines to combine deployment flexibility with infrastructure isolation.

05 / PLANNING

The cost of virtualization

Virtualization can reduce some costs, but it introduces others. Total cost depends on scale, workload, licensing, and operations.

POTENTIAL SAVINGS

What may cost less?

  • Fewer physical servers to purchase
  • Lower power and cooling needs
  • Better hardware utilization
  • Faster provisioning and recovery
  • Less data-center space
COSTS TO PLAN FOR

What may cost more?

  • Hypervisor and management licenses
  • Shared storage and high-speed networking
  • Migration and application testing
  • Staff training and specialist support
  • Backup, monitoring, and security controls
Total cost of ownershipHardware + Software + Operations + Migration + Risk

Compare costs over the same period and include both upfront and ongoing expenses.

06 / WRAP-UP

Benefits, challenges, and conclusion

+

Benefits

Resource consolidation, workload flexibility, faster provisioning, test environments, and improved disaster-recovery options.

−

Challenges

Management complexity, licensing uncertainty, host failure impact, resource contention, and security misconfiguration.

✓

Conclusion

Virtualization is a core infrastructure technique. The best choice—VMs, containers, network virtualization, or a combination—depends on the workload and its isolation, performance, and cost requirements.
